# Local dependency repair

Map each useful workflow to its components, processes and resources, citing manifest/configuration/consumer evidence. Include databases (each named connection separately), caches, queues/workers, object storage, identity, mail and SDK transports. Static inventory is only a starting point; inspect consumers and runtime failures. An absent credential need not block an inferred local simulation. If static inventory misses server, environment or API evidence, inspect source consumers directly (including standard-library servers, environment reads and OpenAPI/Swagger files). Empty helper output does not prove absence, a dependency-free application or that native execution is safe.

Prefer the same database engine with migrations/schema and synthetic related records. A model inferred schema must be labeled provisional: queries and model fields cannot prove triggers, constraints or business rules. Never connect to production, fetch exports or reset external databases. Destructive resets must be confined to a controller-owned disposable service whose identity/network are verified; an environment-name string alone is insufficient.

Prefer runnable protocol-compatible substitutes or existing emulators/development adapters for external APIs. A unit-test fake is not a running local API for a browser/worker. Cover success, error, timeout, empty data, pagination and auth shape when known. Preserve production paths. Prevent workers, seeders/model events, mail and SDK clients from escaping the local network. Network `none` allows same-container loopback simulations, but separate-container network/service orchestration is not implemented by the disposable backend. Existing project Compose/native/service runners can be used under harness permissions; preserve their ownership, networking and persistent data. Choose an isolated runtime where egress restriction is required; native execution alone provides none.

Publish complete copyable setup/start/stop/reset/test/debug commands, including the actual syntax for nonsecret environment overrides and paths. Map available contract operations to documented and probed operations, or explicitly state exclusions and why. Derive only needed synthetic scenarios; do not copy arbitrary example payloads or credentials into reports.

Freeze meaningful assertions before repairs. Run setup twice in the same working directory and database, asserting seed identity appears exactly once. Create extra user records before the primary create/read probe, capture its returned ID and use that ID for read/restart checks. Compare full rows and counts before/after each setup rerun rather than asserting a fixed total; preserve every user record. Two fresh verification copies do not prove setup idempotency. Also test database reopen/persistence, expected failures and an isolated small edit/test cycle. Document and exercise the actual launch modes: Ctrl-C for an owned foreground process, and exact recorded PID/service stop plus listener-closure evidence for an owned background process. Test reset/reseed only with owned disposable data and retain sibling/unrelated data; an unexecuted reset is explicitly unverified, not a working claim. Do not suggest broad directory deletion. Report verified local contracts, inferred simulation and real-provider fidelity separately. Undocumented proprietary semantics remain missing inputs, never invented correctness.

Laravel is an example, not a recognition gate: inspect installed versions, Composer/lockfiles, extensions, Artisan, key/config-cache steps, migrations, named connections, queues/scheduler, storage, factories, routes and frontend builds. Preserve established Sail/Compose conventions. A passing Laravel fixture does not establish universal language/framework support.
