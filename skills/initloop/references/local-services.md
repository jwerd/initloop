# Local dependency repair

Map each useful workflow to its components, processes and resources, citing manifest/configuration/consumer evidence. Include databases (each named connection separately), caches, queues/workers, object storage, identity, mail and SDK transports. Static inventory is only a starting point; inspect consumers and runtime failures. An absent credential need not block an inferred local simulation.

Prefer the same database engine with migrations/schema and synthetic related records. A model inferred schema must be labeled provisional: queries and model fields cannot prove triggers, constraints or business rules. Never connect to production, fetch exports or reset external databases. Destructive resets must be confined to a controller-owned disposable service whose identity/network are verified; an environment-name string alone is insufficient.

Prefer runnable protocol-compatible substitutes or existing emulators/development adapters for external APIs. A unit-test fake is not a running local API for a browser/worker. Cover success, error, timeout, empty data, pagination and auth shape when known. Preserve production paths. Prevent workers, seeders/model events, mail and SDK clients from escaping the local network. Network `none` allows same-container loopback simulations, but separate-container network/service orchestration is not implemented by the disposable backend. Existing project Compose/native/service runners can be used under harness permissions; preserve their ownership, networking and persistent data. Choose an isolated runtime where egress restriction is required; native execution alone provides none.

Publish setup/start/stop/reset/test/debug commands and deterministic seed scenarios that work without Initloop. Freeze meaningful assertions before repairs; test setup reruns, database reopen/persistence, expected failures and an isolated small edit/test cycle. Report verified local contracts, inferred simulation and real-provider fidelity separately. Undocumented proprietary semantics remain missing inputs, never invented correctness.

Laravel is an example, not a recognition gate: inspect installed versions, Composer/lockfiles, extensions, Artisan, key/config-cache steps, migrations, named connections, queues/scheduler, storage, factories, routes and frontend builds. Preserve established Sail/Compose conventions. A passing Laravel fixture does not establish universal language/framework support.
